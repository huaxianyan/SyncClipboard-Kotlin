# SyncClipboard Kotlin v0.2.0

本次更新重构了「关闭接收暂停期间的云端更新」的判定逻辑，并修正了自动下载的去重基准。主要解决：手机剪贴板被系统清空或被其他内容覆盖之后，以前同步过的那份内容再也同步不回来的问题。

## 去重基准改为「本机剪贴板当前内容」

自动下载过去用「这个哈希我处理过」来判断要不要跳过写入。那个字段由上传、下载、归档三条路径共用，只说明处理过，不说明剪贴板里现在是什么。于是会出现：补查把一条内容归档后该字段被对齐成它，之后云端再推同一条内容就被静默丢弃；若此时剪贴板里并不是它（重启后被清空、或被其他内容覆盖），这份内容就再也同步不回来，且记录里没有任何痕迹。

现在新增一份本机剪贴板登记值，在本地复制上报、写入剪贴板成功、延迟写入重试成功三处登记，文本的跳过写入只以它为准：

- 登记值与远端内容一致时跳过写入，并记录一条「远端内容与本机剪贴板相同」记录，不再无声跳过
- 登记值不一致或拿不到时照常写入。未知一律不写入抑制判断，因为把内容写进剪贴板总是安全的，误跳过才会让人拿不到内容
- 登记值只在同一次开机内有效。设备重启后系统剪贴板会被清空而登记值仍在，此时按「拿不到」处理

图片与文件没有可读回的本机状态，仍沿用原来的判断方式。

## 内容时间判据

关闭该选项时，补查路径会用服务端给出的内容时间判断这条内容是不是「本机看不到云端的那段时间里积压的」。判定只比内容时间与判定时刻，并把服务器时钟偏移独立校准，不再与基线互相依赖：

- 内容时间早于判定时刻超过 5 秒的文本不写入剪贴板，改为存入文本历史
- 该判据只用于补查路径。实时推送只会在其他设备刚改完云端时到达，本身就是内容「刚刚」产生的证据，套用判据会把「重新复制一条以前复制过的内容」误判成积压
- 顺便修掉一个漏洞：被归档的内容此前会在下一次补查里绕过陈旧判定被写进剪贴板

服务端不提供「本次到达时刻」，只能给出「首次到达时刻」。因此补查窗口里恰好重传了一条以前出现过的内容时，仍可能被判为积压。这一条要等上游服务端提供接收时间接口后才能彻底闭合，届时客户端以探测方式接入，不需要开关。

## 同步条件上报补齐

SystemUI 扩展的 Binder 掉线此前没有计入自动同步的存活条件，重新连接后会跳过基线，把停机期间云端产生的旧内容写进剪贴板。现在它与锁屏、断网同等对待，掉线时一并清除尚未完成的远端写入。

## 自动同步记录

- 新增「远端内容与本机剪贴板相同」这一条记录，跳过的写入不再无声发生
- 被跳过的陈旧内容会附带内容年龄，例如「15 分钟前的文本未写入剪贴板，已存入历史」

## 应用图标

- 主体应用与系统扩展更换为新的循环箭头图标，背景色 `#B3D3F9`
- 图标位于两个模块共用的品牌资源目录，一处改动同时生效

## 权限与兼容

未改动系统扩展的接口和通信协议，升级主体应用即可，无需重新安装扩展。已安装的服务器方案、加密凭据、同步历史和设置都会保留。

## 安装与升级

普通手动同步只需安装：

```text
app-release.apk
```

如需后台自动同步，再安装同一版本的：

```text
system-extension-release.apk
```

可从 `v0.1.9` 直接覆盖安装。主体应用与系统扩展应使用同一版本。更新系统扩展后必须重新启动设备，使新版本扩展重新载入 SystemUI。

Release 同时提供 `SHA256SUMS`，可用于校验两个 APK 的完整性。
