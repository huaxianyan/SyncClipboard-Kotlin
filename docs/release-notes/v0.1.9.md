本次更新修复两个问题。一是关闭「接收暂停期间的云端更新」后，锁屏期间的远端文本仍可能在解锁后写入剪贴板。二是特定网络故障可能导致自动同步进程退出。

## 主要更新

- **同步检查锁定状态**：SystemUI 扩展在 Binder 调用期间检查设备锁定状态并完成剪贴板写入，不再把任务投递到主线程后提前报告成功。
- **写入前复查条件**：远端内容真正写入前再次检查设备、网络和自动同步条件。
- **清空未完成的写入**：关闭「接收暂停期间的云端更新」时，进入锁屏或失去网络条件会清除尚未完成的远端剪贴板写入。
- **锁屏失败不重试**：锁屏期间的 Binder 写入失败不会保留到解锁后重试。
- **保留有界重试**：设备正常解锁期间的临时 Binder 故障仍保留原有的有界重试能力。
- **修复恢复崩溃**：恢复基线请求失败后 HTTP 兜底请求再次失败可能抛出未捕获异常，现已修复。
- **不再退出进程**：HTTPS 握手中断、临时断网和服务器不可达现在只进入错误状态与退避重试，不会终止 `:sync` 进程。
- **通道策略不变**：SignalR WebSocket 仍是主要通道，HTTP 兜底仍限制为最多每 5 分钟一次。

实机验证：锁屏期间产生的远端文本不会覆盖手机剪贴板，解锁后新产生的远端文本仍可正常写入。

可从 `v0.1.8` 直接覆盖安装，现有服务器方案、加密凭据、同步历史和设置会继续保留。更新系统扩展后必须重新启动设备，使新版本扩展重新载入 SystemUI。

暂停恢复判定的边界见 [架构说明的暂停与恢复边界](https://github.com/huaxianyan/SyncClipboard-Kotlin/blob/v0.1.9/docs/architecture.md#暂停与恢复边界)。
