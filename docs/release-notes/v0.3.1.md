本次更新改进了「不接收暂停期间的云端更新」的判定方式。旧判据只能看内容第一次到达云端的时刻，分不清「暂停期间提交」和「很久以前就存在」。现在直接与你恢复同步的时刻比较，判定范围更清楚。

## 改进

- **暂停判定更准确**：以服务端记录的内容提交时刻为准。恢复同步之前提交的内容只归档进历史，不写剪贴板；恢复之后提交的正常写入。容差从 5 秒收紧到 1 秒，误判范围更小。
- **重新复制的内容不再被误判**：同一份内容以前提交过时，旧判据记的时刻永远是最早那次，看起来总是「很久以前」。现在每次提交都会更新时间，重新复制会被当成刚提交的内容处理。
- **少一次网络请求**：判定所需的时间随剪贴板内容一起下发，不再为每条文本额外查询历史记录接口。历史被清理或超过保留期时，也不会因此失去判定能力。
- **推送与补查统一判定**：两条路径使用同一套规则，不再出现「推送收到就写入、补查收到就跳过」的差异。

这项改进依赖服务端提供内容提交时刻。官方服务端 `v3.3.2` 起已支持，更早的服务端与 WebDAV、S3 部署仍沿用原有判据，行为不变。

判定规则与降级顺序见 [架构说明](https://github.com/huaxianyan/SyncClipboard-Kotlin/blob/v0.3.1/docs/architecture.md#暂停与恢复边界)。
